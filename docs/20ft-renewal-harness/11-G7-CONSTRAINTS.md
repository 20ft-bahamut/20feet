# 11. G7 / 20ft Studio 필수 구현 제약

이 문서는 일반적인 웹사이트 개편 관례보다 구체적인 대상 제약을 정의한다. 상위 시스템·보안 규칙과 저장소의 실제 개발 지침을 무효화하지 않는다.

## 대상 확정

사용자는 그누보드 G7에서 직접 만든 **20ft Studio 사용자 템플릿**으로 현재 홈페이지를 운영하고 있다. 사용자 제공 관리자 화면의 관찰값:

- 템플릿: `20ft Studio`, 현재 활성, `v0.2.0`.
- 작성자: `20ft`.
- 설명: `20ft 공식 Website User Template (Portfolio / SuperBify / Project Inquiry)`.
- 의존성 표시: `20ft 콘텐츠`, `게시판`.
- 코드 편집·레이아웃 편집 UI가 존재.
- 관리자 화면 하단 G7 `v7.0.8`.

이름과 버전은 단서이며 디스크 경로와 패키지 ID가 아니다. `20ft-studio` 같은 폴더 이름이나 훅·설정 파일 이름을 근거 없이 생성하지 않는다. 현재 소스에서 메타데이터와 등록 관계를 찾는다.

## 변경 대상과 금지 사항

| 대상 | 방침 |
|---|---|
| 20ft Studio 템플릿 | 기존 패키지를 중심으로 구조·문구·스타일·페이지 표현 개편 |
| 20ft 콘텐츠 의존성 | 실제 역할 조사. 콘텐츠/문의에 필요하면 최소 범위로 확장 |
| 게시판 의존성 | 현재 사용 관계와 접근 권한 보존 |
| G7 코어·기본 관리자 | 직접 수정하지 않는 것이 원칙 |
| Basic 템플릿 | 대체 활성화하거나 수정하지 않음 |
| SuperBify Commerce Minimal | 본 홈페이지 대체 템플릿으로 설치·활성화하지 않음 |
| SuperBify 제품 자료 | 기존 콘텐츠·URL·버전 설명 보존 및 필요한 링크 정리 |

G7 유지라는 말은 모든 PHP·JS 파일을 마음대로 고쳐도 된다는 뜻이 아니다. 사용자 템플릿과 커스텀 확장 코드의 경계를 먼저 확인한다. 새 기능 때문에 코어 수정이 필요하다고 보이면 공식 확장 방식·기존 모듈 재사용·커스텀 모듈 대안을 조사한다. 해결되지 않으면 이유를 보고하고 다른 작업은 계속한다.

## 실제 소스에서 확인할 사항

1. G7 설치·배포 방식과 현재 버전, 실제 프로젝트 런타임.
2. 20ft Studio 메타데이터, 패키지 식별자, 진입점, 레이아웃·템플릿·자산 경로.
3. 템플릿 활성 상태와 레이아웃 편집 값의 저장 위치.
4. 사용자 화면의 라우트 등록과 페이지 콘텐츠를 가져오는 실제 경로.
5. 20ft 콘텐츠와 게시판의 패키지 ID, 데이터 모델, 권한, 제공 API.
6. 문의 기능이 비활성인 이유와 기존 구현 위치.
7. 자산 빌드·캐시·패키징·업데이트·설정 마이그레이션 관례.

G7 API가 불확실하면 설치된 소스·동봉 문서·버전에 맞는 공식 자료를 확인한다. 그누보드 5의 테마 디렉터리, 함수, 스킨 관례를 자동 적용하지 않는다. 이 하네스는 확인되지 않은 G7 API 시그니처를 지정하지 않는다.

## 레이아웃 편집 호환성

레이아웃 편집 버튼이 있다는 사실만으로 모든 콘텐츠가 편집 가능하다고 가정하지 않는다. 실제 편집 스키마와 저장값을 확인한다.

- 기존에 관리하던 로고·메뉴·섹션·링크·텍스트의 편집 가능성을 보존한다.
- 신규 섹션 설정은 프로젝트 방식에 맞는 기본값과 이전 값 호환 처리를 둔다.
- 이미 저장된 사용자 설정을 새 기본값으로 일괄 덮어쓰지 않는다.
- 구조 변경으로 기존 값의 변환이 필요하면 명시적인 매핑과 복구 방법을 제공한다.
- 운영 관리자의 ‘초기화’ 버튼을 눌러 해결하는 방식을 기본 절차로 삼지 않는다.
- 소스 변경이 DB 저장 레이아웃보다 우선하는지/가려지는지 확인한다. 코드를 바꿨는데 화면이 그대로인 문제를 캐시로 단정하지 않는다.

## 콘텐츠와 문의

포트폴리오·SuperBify·문의가 20ft 콘텐츠에서 관리되는지 확인한다. 확인 전 모델 구조를 지어내지 않는다. 템플릿에 사례 전체를 하드코딩하여 기존 관리 기능을 없애지 않는다. 서버 문의 처리는 지원되는 모듈/플러그인/라우트 확장 위치에 둔다.

새 서비스 페이지도 G7의 실제 페이지 구조에 맞춰 구성한다. 독립 SPA나 별도 프런트엔드를 만들고 겉으로만 연결하는 방식은 기본 범위에서 제외한다.

## 회귀 검증

- 기존 설정을 가진 20ft Studio가 정상 렌더링되는가?
- 관리자 콘텐츠 수정이 사용자 화면에 반영되는가?
- 지원되는 레이아웃 설정을 로컬/테스트 환경에서 변경·복원할 수 있는가?
- 의존성 확인과 패키지 등록이 유지되는가?
- 기존 제품·사례 조회와 메뉴가 동작하는가?
- 인증/권한이 필요한 문의 관리 경로가 보호되는가?
- 변경분이 G7 코어와 다른 템플릿으로 새어나가지 않았는가?

운영 관리자 화면의 활성 템플릿 스위치·설정·콘텐츠를 검증 목적으로 임의 변경하지 않는다. 로컬 또는 승인된 테스트 환경에서 검증한다. 실제 패키지 버전 변경은 저장소 릴리스 관례에 맞추고, 하네스 관찰 버전을 최신 버전이라고 강제하지 않는다.
