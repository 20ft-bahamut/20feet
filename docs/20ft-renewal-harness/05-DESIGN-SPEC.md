# 05. 화면 디자인 기준

## 방향

실제 작업을 확인하고 상담할 수 있는 제작 사업의 홈페이지로 구성한다. 기존 크림색·네이비·주황색과 로고는 활용할 수 있다. 전면 개편은 정보구조와 콘텐츠의 범위를 뜻하며 색상·로고까지 무조건 바꾸라는 뜻이 아니다.

## 첫 화면

- 상단 메뉴와 H1에서 제작업이라는 사실을 즉시 읽을 수 있어야 한다.
- 데스크톱은 명확한 문구와 실제 작업 화면을 균형 있게 배치한다. 구현된 사례 화면에 제작물 유형을 짧게 붙인다.
- 큰 흐릿한 로고를 주 비주얼로 사용하지 않는다. 로고는 브랜드 식별 역할에 집중한다.
- 모바일은 제목·설명·주요 행동을 먼저 보여주고 화면 이미지는 이어서 배치한다.
- 장식 때문에 과도한 빈 공간이나 고정 100vh를 강제하지 않는다. 텍스트가 잘리거나 문의 버튼이 가려지지 않아야 한다.

## 콘텐츠 표현

- 사례 이미지는 읽을 수 있는 비율로 보여주고 필요하면 상세로 확대한다. 실제 기능이 보이지 않는 작은 목업 여러 개로 채우지 않는다.
- 화면 자산이 없으면 공개 가능한 실제 데모를 캡처하거나 기존 자산을 활용한다. 가상 고객사 화면·로고·성과 이미지를 만들어 실적처럼 쓰지 않는다.
- 카드마다 제목·한 문장 설명·행동의 순서를 명확히 한다. 모든 내용을 같은 카드 모양으로 반복하지 않는다.
- 신뢰 영역에 임의의 로고 행렬·별점·만족도·프로젝트 숫자를 넣지 않는다.
- ‘Software Studio’, ‘Digital Garage’, ‘JUST FOR FUN’은 소개의 보조 내용으로 한정한다.
- 장식 영문 라벨을 읽어야 이해할 수 있는 구조를 피한다.

## 반응형과 접근성

- 360px, 390px, 768px, 1280px 이상의 화면에서 검증한다. 기기 숫자 자체보다 가로 넘침·가독성·메뉴와 폼 사용성을 확인한다.
- 본문 기본 크기는 약 16px를 출발점으로 하고 한국어 줄바꿈과 충분한 행간을 적용한다.
- 버튼과 메뉴의 터치 영역은 가급적 44px 이상 확보한다.
- 키보드 포커스, 메뉴 열림 상태, Esc 닫기와 적절한 포커스 이동을 제공한다.
- 이미지 대체 텍스트는 화면의 역할을 설명한다. 장식은 빈 대체 텍스트로 처리한다.
- 폼은 시각적 레이블과 실제 연결을 제공한다. placeholder만 레이블로 쓰지 않는다.
- 색상만으로 오류·선택 상태를 전달하지 않는다. 대비 기준을 확인한다.
- 애니메이션은 최소화하고 reduced-motion을 존중한다. 자동 재생 영상·커서 효과·강제 가로 스크롤을 기본으로 추가하지 않는다.

## 자산과 성능

기존 이미지 권한과 내용 공개 가능 여부를 확인한다. 개인정보가 포함된 관리자 화면은 가린다. 이미지 크기와 포맷을 최적화하고 레이아웃 이동을 줄인다. 첫 화면 이미지와 하단 이미지 로딩 우선순위를 구분한다. 단순 카드·메뉴를 위해 대형 UI 라이브러리를 추가하지 않는다.
