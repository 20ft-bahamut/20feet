# 09. 완료 기준

각 항목은 PASS / FAIL / BLOCKED / NOT RUN으로 표시하고 화면·검사 출력·코드 위치 등 근거를 남긴다. 미실행을 통과로 표시하지 않는다.

## 사업 메시지

- [ ] 첫 화면의 큰 제목에 홈페이지·쇼핑몰·웹프로그램 제작이 명확하다.
- [ ] 일반 고객의 문의가 주 행동이며 사례 보기가 보조 행동이다.
- [ ] 개발자 용어를 몰라도 세 서비스의 차이를 이해할 수 있다.
- [ ] 외주 → 담당자의 경험 → 자체 제품의 우선순위가 메뉴와 화면에 반영된다.
- [ ] ‘가능성’, ‘혁신’ 같은 추상어가 실제 제작 설명을 대신하지 않는다.
- [ ] 최초 방문자 이해 여부는 가능하면 사용자 검토로 확인한다. 에이전트가 실제 고객 실험을 했다고 보고하지 않는다.

## 사실과 콘텐츠

- [ ] 자체 데모와 고객 프로젝트를 목록·상세 모두에서 구분한다.
- [ ] 미확인 경력·고객·팀 규모·성과·가격·기간·지원 약속이 없다.
- [ ] 퓨어폴의 CTO라는 직함을 미검증 단독 수행 실적으로 확대하지 않았다.
- [ ] 서비스 상세가 이름만 다른 복제 문장이 아니며 각 고객의 질문에 답한다.
- [ ] 서비스/사례의 관련 문의 링크가 작동한다.
- [ ] 화면에 TODO·가상 연락처·임시 이미지·빈 섹션이 없다.

## G7 및 기존 기능

- [ ] 실제 G7 버전과 활성 20ft Studio 패키지 경로를 확인했다.
- [ ] G7 코어 파일을 수정하지 않았다. 발견된 기존 수정은 구별해 기록했다.
- [ ] 기존 20ft Studio 식별자와 활성 설정이 보존된다.
- [ ] 20ft 콘텐츠·게시판 의존성과 콘텐츠 조회가 정상이다.
- [ ] 레이아웃 편집에서 관리하는 값과 신규 기본값이 충돌하지 않는다.
- [ ] 기존 설정을 읽어도 렌더링이 깨지지 않으며 강제 초기화가 없다.
- [ ] 기존 사례·SuperBify 상세 URL이 유지되거나 검증된 리디렉션이 있다.
- [ ] 제품 데모·GitHub 등 외부 링크가 정확하다. 표시 라벨과 목적지가 일치한다.
- [ ] 페이지별 제목·메타·canonical·sitemap은 기존 환경과 일관된다.

## 화면

- [ ] 홈, 서비스, 사례 상세, 문의를 모바일/데스크톱에서 확인했다.
- [ ] 가로 넘침, 잘린 제목, 이미지 찌그러짐, 버튼 겹침이 없다.
- [ ] 터치·키보드로 메뉴와 문의 폼을 사용할 수 있다.
- [ ] 포커스, 레이블, 오류 안내, 대비와 이미지 대체 텍스트가 적절하다.
- [ ] 모바일 메뉴와 고정 영역이 폼/본문을 가리지 않는다.
- [ ] 이미지에 공개하면 안 되는 고객·관리자 개인정보가 없다.

## 문의

- [ ] 필수값 누락·잘못된 이메일·길이 초과가 서버에서도 차단된다.
- [ ] 저장/전송 성공일 때만 성공 상태를 표시한다.
- [ ] 실패 후 입력값을 보존하고 재시도할 수 있다.
- [ ] 중복 클릭과 중복 접수 위험을 검증했다.
- [ ] 스팸 방어·CSRF·권한·출력 이스케이프를 기존 G7 방식에 맞춰 확인했다.
- [ ] 문의 전문·비밀키·개인정보가 콘솔이나 서버 로그에 노출되지 않는다.
- [ ] 접수된 문의를 운영자가 확인할 방법이 있다.
- [ ] 실제 수신 설정과 개인정보 안내가 확인되었거나 배포 차단 항목으로 명시되어 있다.
- [ ] 로컬 테스트와 외부 실제 수신 확인을 구분해 보고했다.

## 엔지니어링

- [ ] 기존 지침에 따른 검사·빌드·테스트를 수행했다.
- [ ] 새로운 실행 오류·치명적인 콘솔 오류가 없다.
- [ ] 기존 사용자 변경과 기존 데이터가 보존된다.
- [ ] 새 의존성의 필요성과 설치 이유가 기록되어 있다.
- [ ] 마이그레이션이 있으면 원복과 데이터 보존 절차가 있다.
- [ ] 운영 배포·유료 서비스 변경·실제 문의 전송을 승인 없이 하지 않았다.

## 상태 판정

기능·화면 구현이 끝나도 실제 수신 설정이나 필수 정책이 미정이면 `구현 완료 / 운영 공개 차단 있음`으로 보고한다. 핵심 화면이나 문의 서버 처리가 미완료면 `부분 완료`다. 모든 필수 조건과 운영 연결이 검증되어야 `배포 승인 요청 가능`이다.
