# 03. IA와 고객 동선

## 상단 메뉴

**제작 서비스 / 제작 사례 / 진행 안내 / 이십피트 소개 / [제작 문의]**

한글 라벨을 기본으로 한다. 로고는 홈으로 연결한다. 제작 문의를 주요 버튼으로 일관되게 표시한다. SuperBify는 푸터의 ‘자체 개발 제품 · SuperBify’와 소개·관련 사례에서 연결한다.

## 권장 경로

| 경로 | 목적 |
|---|---|
| `/` | 어떤 제작을 맡길 수 있는지 이해시키고 사례·상담으로 연결 |
| `/services` | 세 가지 제작 분야를 비교하고 자신에게 맞는 서비스 선택 |
| `/services/website` | 홈페이지 제작·개편 의뢰 안내 |
| `/services/commerce` | 쇼핑몰·이커머스 구축 의뢰 안내 |
| `/services/web-development` | 맞춤형 웹프로그램·업무 시스템 의뢰 안내 |
| `/portfolio` | 기존 경로 보존, 화면의 메뉴명은 제작 사례 |
| `/portfolio/[existing-slug]` | 기존 사례 경로 보존 및 설명 보강 |
| `/process` | 상담부터 범위 협의·제작·검수·오픈까지 안내 |
| `/about` | 담당자의 경력·실제 역할·일하는 방식 |
| `/inquiry` | 필요한 정보만 받아 실제 접수 |
| `/superbify` 및 기존 상세 | 제품 정보와 개발자 대상 문서 보존 |

경로는 제안이다. 기존 라우트 관례에 맞춰 조정할 수 있지만 메뉴 역할과 고객 동선은 유지한다. 서비스 상세 세 페이지는 실질적인 내용이 있어야 한다. 동일 문장에 단어만 바꾼 검색용 페이지를 만들지 않는다.

## 메인 순서

1. 업종·제작 분야·실제 화면·제작 문의와 사례 보기.
2. 세 가지 제작 서비스: 고객 상황, 제작물 예시, 상세 링크.
3. 대표 사례: 시스템 사례와 커머스 데모를 유형 표기하여 노출. 홈페이지 사례가 없으면 만들지 않는다.
4. 담당자의 경험: 20년 이상 웹 개발이라는 기존 소개와 실제 기획·개발 경험을 사례로 연결.
5. 진행 방식: 고객이 어떤 내용을 준비하고 언제 확인하는지.
6. 자주 묻는 질문: 기획서, 비용·기간 산정, 기존 사이트 개선, 오픈 후 지원.
7. 문의: 부담을 낮추는 설명과 작동하는 문의 경로.

SuperBify의 제품 카드 세 개를 메인 중심에 반복 배치하지 않는다. 경험 영역에 짧은 소개 링크를 추가할 수 있다. 문의 직전에 브랜드 철학을 길게 삽입하지 않는다.

## 필수 고객 시나리오

### 회사 홈페이지 고객
홈 → 홈페이지 제작 → 관련 화면/가능 범위 → 진행 안내 → 문의. 기술 용어를 이해하지 않아도 경로를 따라갈 수 있어야 한다.

### 쇼핑몰 고객
홈 → 쇼핑몰 제작 → 자체 제작 데모 확인 → 기본 쇼핑 흐름과 맞춤 개발 범위 확인 → 문의. 데모를 고객 납품 실적으로 오인하지 않아야 한다.

### 업무 프로그램 고객
홈 → 웹프로그램 개발 → 퓨어폴 사례에서 문제·사용자·기능 연결 확인 → 자신의 업무 설명으로 문의. 상세 명세서 제출을 필수로 만들지 않는다.

### 개발자·제품 방문자
기존 `/superbify` 링크 또는 푸터 → 제품 목록 → 상세·저장소·데모. 기존 제품 유입 경로가 끊기지 않아야 한다.

## 메뉴와 링크 규칙

- 메뉴명·페이지 제목·버튼 목적이 서로 일치한다.
- 페이지 중간/끝에서 다음 행동이 명확하다. 모든 버튼을 문의로만 연결하지 않는다.
- 서비스별 문의 진입 시 유형을 미리 선택할 수 있으나 사용자가 변경 가능해야 한다.
- 기존 링크를 새 디자인 때문에 404로 만들지 않는다.
- 푸터에는 서비스, 사례, 소개, 문의, SuperBify, 확인된 연락 방법, 실제 필요한 개인정보 안내를 정돈한다. 사업자 정보를 만들어 넣지 않는다.
