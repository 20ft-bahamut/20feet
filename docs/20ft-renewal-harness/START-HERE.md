# Claude Code 시작 프롬프트

아래 내용을 실제 사이트 저장소에서 Claude Code에 전달하세요.

```text
이 저장소의 20ft 홈페이지를 외주 수주 중심으로 전면 개편해줘.

이 홈페이지는 그누보드 G7 기반이야. G7을 유지하고 현재 버전과 템플릿·플러그인 구조를 소스로 확인한 뒤 작업해. G7 코어 비수정을 원칙으로 하고 다른 프레임워크로 이관하거나 별도 웹앱으로 재구축하지 마. 그누보드 5의 구조·함수·훅을 G7에 추측 적용하지 마. 특히 11-G7-CONSTRAINTS.md를 필수로 따라줘.

정확한 수정 대상은 현재 활성화된 사용자 템플릿 `20ft Studio`야. 관리자 화면에는 템플릿 v0.2.0, G7 v7.0.8, 의존성으로 `20ft 콘텐츠`와 `게시판`이 보이고 코드 편집·레이아웃 편집 기능이 있어. 이 값은 소스에서 재확인하고 실제 디렉터리명이나 확장 API는 추측하지 마. 기존 20ft Studio의 식별자·콘텐츠 연동·레이아웃 편집 호환성을 보존하면서 개편해. 새 템플릿을 별도로 설치하거나 Basic/SuperBify Commerce Minimal 템플릿을 활성화하는 방식으로 대체하지 마.

먼저 20ft-renewal-harness/README.md와 번호가 붙은 모든 명세를 읽고, 저장소의 기존 CLAUDE.md, AGENTS.md 및 개발 지침을 확인해줘. 이 패키지에 있는 templates를 바탕으로 작업 상태와 검증 기록을 유지해줘.

사업 우선순위는 1. 외주 수주 2. 개발자 개인브랜드 3. SuperBify야. 첫 방문자는 일반 기업 담당자·사업자이며, 홈페이지·쇼핑몰·맞춤형 웹프로그램을 의뢰하려고 방문해. 개발자 용어와 추상적인 스튜디오 철학을 해석하지 않아도 무엇을 맡길 수 있는지 이해해야 해.

이번 일은 카피 몇 줄이나 색상을 바꾸는 작업이 아니야. 현재 소스를 먼저 분석한 다음 메뉴와 IA, 메인·서비스·사례·소개·진행 안내·문의 페이지, 실제 문의 동선, 모바일 화면을 함께 개편해줘. 기존 스택·콘텐츠·관리 기능·제품 URL은 합리적으로 재사용하고, 근거 없이 프레임워크를 교체하거나 데이터와 기존 기능을 삭제하지 마.

공개 사이트를 확인한 내용과 제안 카피는 하네스에 들어 있어. 실제 저장소와 다른 부분은 소스를 기준으로 근거를 기록해서 보정해. 사실로 확인된 경력과 사례만 사용하고, 가격·기간·인력·실적·고객 평가·운영 지원을 만들어내지 마. 자체 데모는 실제 고객 납품 사례와 명확히 구분해.

조사 보고서나 계획만 제출하고 작업을 멈추지 말고, 권한과 환경이 허용하는 범위에서 구현과 로컬 검증까지 진행해줘. 분석 후 변경 방향을 짧게 공유하되 통상적인 가역적 구현마다 승인을 기다리지 마. 다만 실제 연락처·문의 수신 설정·계정 권한처럼 정확한 입력이 필요한 것은 한 번에 정리해서 질문하고, 답이 없어도 독립적으로 가능한 나머지 작업은 계속해줘. 답이 없다는 이유로 임의의 값을 넣지 마.

문의 기능은 화면만 만드는 것으로 완료 처리하지 마. 기존 수신 경로를 조사하고, 실제 저장 또는 전송의 성공·실패에 맞는 응답과 재시도 흐름을 구현해줘. 외부로 테스트 메일·메시지를 보내는 것은 별도 승인을 받고, 승인 전에는 로컬 테스트 수신기로 검증해. 수신 설정이 없으면 이를 명확한 배포 차단 항목으로 남겨줘. 문의 내용이나 비밀키를 로그에 노출하지 마.

각 단계에서 실행한 검사, 결과, 미완료 항목을 기록하고 마지막에는 로컬 프리뷰와 화면, 변경 경로 목록, 테스트 결과, 배포 전 필요한 입력을 보여줘. 빌드 통과만으로 완료라고 하지 말고 하네스의 고객 시나리오와 접근성·반응형·문의 실패 시나리오를 검증해.

운영 사이트에 배포하거나 유료 서비스를 가입·변경하거나 기존 문의·고객 데이터를 삭제하지 마. 운영 배포는 검토 가능한 결과와 미해결 항목을 제시한 뒤 별도 승인받아.

지금 저장소 분석부터 시작해줘.
```

