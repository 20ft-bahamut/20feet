# Information Architecture

## 1. IA 원칙

20ft는 정형화된 상품 패키지를 판매하는 에이전시가 아닙니다.

따라서 사이트는 “서비스를 많이 설명하는 회사소개서”보다:

> **무엇을 만들었는가 → 어떤 기술 활동을 하는가 → 누가 만드는가 → 일을 맡기려면 어떻게 하는가**

를 보여주는 구조로 설계합니다.

## 2. 최종 Sitemap

```text
20ft
│
├── HOME                         /
│
├── PORTFOLIO                    /portfolio
│   └── PROJECT DETAIL           /portfolio/{slug}
│
├── SUPERBIFY                    /superbify
│   └── PROJECT DETAIL           /superbify/{slug}
│
├── ABOUT                        /about
│
└── PROJECT INQUIRY              /inquiry

Utility
├── Privacy Policy               /privacy
└── Error Pages                  /404, /403, /500 ...
```

## 3. Header

```text
[20ft Full/Compact Logo]

Portfolio
SuperBify
About

[ 프로젝트 문의 ]
```

정책:

- `Services` 없음
- `Works` 대신 `Portfolio`
- `Contact` 별도 메뉴 없음
- 프로젝트 문의가 Contact 기능을 겸함
- Desktop 메뉴 3개 + CTA
- Mobile에서는 compact logo + menu trigger

## 4. HOME

Home은 5개의 본문 섹션만 사용합니다.

```text
01 HERO
02 SELECTED PORTFOLIO
03 SUPERBIFY
04 ABOUT 20FT
05 JUST FOR FUN + PROJECT INQUIRY
FOOTER
```

`Portfolio`가 “우리가 무슨 일을 하는지”를 보여주는 핵심 증거입니다.

## 5. PORTFOLIO

### 목적

서비스 메뉴를 대신해 20ft의 작업 범위와 실력을 보여줍니다.

### List

- 프로젝트명
- 한 줄 설명
- Category
- Status
- Year
- Thumbnail/Cover
- Detail link

### Detail

```text
Overview
Problem / Context
What We Did
System / Approach
Key Screens
Result / Current State
Stack
Related Links
Next Project
```

## 6. SUPERBIFY

SuperBify는 단일 제품 홍보 페이지가 아닙니다.

**20ft가 앞으로 만드는 G7 Extension / Developer Tool / Experiment를 관리하고 공개하는 Project Board**입니다.

### List

- Project Name
- Type
- Target
- Status
- Version
- Updated
- Summary

### Detail

- Overview
- Why
- Features
- Requirements
- Install
- Usage
- Changelog
- GitHub / SIR
- Release information

## 7. ABOUT

- 20ft 이름과 철학
- 현재 Software Studio 정체성
- Founder의 개발 배경
- JUST FOR FUN 태도

Mission/Vision/Value 식 기업 문구는 사용하지 않습니다.

## 8. PROJECT INQUIRY

정형화되지 않은 프로젝트를 접수합니다.

URL: `/inquiry`

CTA Label: **프로젝트 문의**
